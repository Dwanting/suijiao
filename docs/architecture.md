# 实现与验证边界

## 事件链路

普通键盘通过 Carbon `RegisterEventHotKey` 注册的 `⌃⌥⌘J` 触发唤起，`⌃⌥⌘I` 触发输入框校准。

Free3 通过 IOKit 进行非独占监听。先按硬件 ID 筛选，再确认产品名 `Free3-P`，逐个设备打开、注册回调和安排 RunLoop。直接组合键识别依赖观察到左 Control、左 Option、左 Command 已按下，随后收到 J。唤起入口设置 0.7 秒防重复窗口，降低系统快捷键与 HID 路径同时触发时的重复处理。

两条唤起路径都进入同一个处理函数：使用 bundle identifier `com.openai.codex` 查找并激活应用，然后在辅助功能权限允许时设置焦点。

焦点优先使用用户校准的 `AXUIElement`；校准仅接受目标应用前台的文本区或文本栏。引用失效时尝试查找当前窗口中带已知输入提示的文本区，仅在候选唯一时设置焦点。超时后提示重新校准。此方法尚未验证能稳定应对多个窗口、客户端更新或对话切换。

## 语音与提交

随叫不合成语音触发按键，也不录音。Free3 的左 Control 和 Enter 继续由系统传给当前应用，由豆包处理免提输入，由聊天客户端决定 Enter 是发送还是换行。

桌宠的 listening 状态只是本地按键观察结果，不读取豆包录音状态。桌宠没有操作按钮；显示隐藏只影响 `NSPanel`，不会停止快捷键和 HID 监听。

## 状态与持久化

- `petPosition`：UserDefaults 中的桌宠位置。
- `rememberedInput`：当前进程中的辅助功能控件引用，不写入磁盘。
- `/tmp/suijiao-runtime-status.json`：运行状态与最后事件，每两秒覆盖。不包含输入框文本、转写或录音。
- 独立诊断脚本：输出原始硬件按键报告，默认运行十分钟，可通过首个参数调整秒数。

## 验证状态与回归范围

已有证据包括本地 Swift 编译、应用签名校验、静态视图渲染、Free3 原始事件、普通键盘全局快捷键回调，以及外部豆包免提输入的人工测试。

2026-11-25，使用者确认当前版本在其 Mac mini、Free3、Codex 桌面客户端与豆包输入法环境中完整可用。项目状态为已验证可用。

后续回归范围包括组合键直接识别后的完整唤起、输入框校准与恢复焦点、桌宠拖动及显示隐藏，以及权限变更后的恢复。其他硬件、固件、客户端版本和多窗口组合仍需单独验证。注册返回成功、应用打开回调成功、控件引用存在，都不能替代实际焦点验证。

后续修改核心代码时，先在 `build/` 验证，不自动覆盖正在使用的应用。确定构建版本后再进行权限授权，避免多次 ad-hoc 签名让用户重复授权。
