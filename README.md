# 随叫 · Suijiao

随叫，随到。

一个面向 macOS 的物理按键语音工作台原型：通过 Free3 小键盘唤起 Codex，回到聊天输入框，再使用豆包输入法说出需求。

桌面上的奶白色小精灵负责陪伴感：呼吸、眨眼、拖动和简单的状态动画。日常操作入口是物理按键，桌宠没有唤起或录音按钮。

<img src="docs/assets/companion.png" alt="随叫桌面小精灵，头顶显示随叫，随到。" width="250">

> **开发中原型，尚未完成端到端验收。** 已实现按键监听、全局快捷键、输入框校准和桌宠界面；唤起 Codex 并可靠聚焦输入框仍需在实际环境中验证。请勿将本仓库理解为已经稳定可用的正式版本。

## 环境要求

- macOS 13 或更高版本，安装 Xcode Command Line Tools，提供 Swift 编译器。
- 当前开发环境为 Apple Silicon Mac；构建脚本按本机架构编译。Intel 构建未验证。
- Codex 所在的 ChatGPT 桌面应用。当前目标 bundle identifier 固定为 `com.openai.codex`。
- 豆包输入法，并已添加到 macOS 输入法列表。
- 若使用物理小键盘，需要蓝牙连接的 Free3-P。普通键盘也能测试全局唤起快捷键。
- 本应用不需要 OpenAI API Key，不替代 Codex 或豆包客户端。

## 从源码构建

```bash
xcode-select --install  # 已安装 Command Line Tools 时跳过
bash scripts/build.sh
```

产物位于 `build/Suijiao.app`。在 Finder 中双击打开，菜单栏会出现“随叫”，并显示桌面小精灵。应用不显示 Dock 图标。

构建脚本仅生成、签名并检查应用，不自动运行、安装、覆盖其他目录的应用，也不会启动录音。首次使用请选定一个固定应用路径，再为该路径下的应用授权，避免运行多个副本。

本项目采用本地 ad-hoc 签名，**未经过 Developer ID 签名或 Apple 公证**。重新编译、签名或更换应用副本后，macOS 可能使已有授权失效；系统设置中开关显示开启，也不代表当前运行版本已获得权限。调试时先固定构建版本，再完成授权与验收。

## 首次设置

### 1. 授予权限

在“系统设置 → 隐私与安全性”中，为当前使用的随叫应用开启：

| 权限 | 用途 |
| --- | --- |
| 辅助功能 | 读取用户校准的输入控件并设置焦点 |
| 输入监控 | 读取匹配的 Free3 设备按键 |

普通键盘的全局唤起快捷键通过 Carbon 注册，不依赖 Free3 的输入监控；定位输入框仍依赖辅助功能。录音权限由豆包输入法管理。

授权后退出并重新打开随叫。如果重新构建后权限失效，可在对应权限列表中移除旧条目，再添加实际运行的应用。不要为了排查单个配件而重置整个系统蓝牙或其他应用的授权。

### 2. 配置豆包输入法

将豆包的**免提模式**快捷键设置为**左 Control（左 ⌃）**。若“长按模式”占用了同一个快捷键，先将其调整为其他键。选中实际使用的麦克风，例如 DJI 接收器 `Wireless Mic Rx`。

测试时先切换到豆包输入法，把光标放入可编辑文本框，使用普通键盘短按左 Control：应能开始语音，再按一次结束。随叫不主动切换系统输入法，也不检查豆包是否正在录音。

### 3. 配置 Free3

在翰林阅客户端的“自定义”页面设置，保存后断开 USB，再通过蓝牙连接 `Free3-P`：

| 物理按键 | 映射 | 日常动作 |
| --- | --- | --- |
| 上键 | 左 Control / ⌃L | 豆包开始或结束免提语音输入 |
| 中键 | Enter | 由当前应用处理回车；聊天客户端配置为回车发送时提交消息 |
| 下键 | Control + Option + Command + J | 唤起 Codex 并尝试定位输入框 |

下键在虚拟键盘中选 **⌃L + ⌥L + ⌘L + J**。不使用 F8，避免触发媒体播放；当前版本也不使用 F13 或双击唤起。

Free3 的 USB 模式和蓝牙模式可能发送不同键值。USB 主要用于配置，日常测试请断开数据线、切换到 P 档并确认蓝牙已连接。自定义配置后可能需要删除旧蓝牙配对并重新连接。

当前代码只匹配实测设备：`Free3-P`，Vendor ID `1452`，Product ID `556`。其他硬件版本或固件可能使用不同标识，需要先检测再适配。

参考：[Free3 官方快速指南](https://hanlinyue.com.cn/docs/Free3)、[官方 Vibe Coding 设置教程](https://hanlinyue.com.cn/1776308564701)。官方语音教程要求应用 1.3.3、Free3 固件 V0.12 或更高，并采用单击免提模式；开发中曾检测到 V0.10，不能据此声称新版固件已验证。

## 使用流程

### 校准输入框

1. 保持随叫运行，手动打开目标 Codex 对话。
2. 用鼠标点击**聊天输入框**，确保光标已经在其中。
3. 使用普通键盘按 **⌃⌥⌘I**（Control + Option + Command + I）。
4. 菜单栏显示“已记住输入框”后，再测试唤起。

这是一次定位校准，不是第二个唤起步骤。控件引用仅保存在当前进程内；重启随叫、重建窗口或输入控件后，可能需要重新校准。校准后也不能保证客户端更新、切换对话或关闭窗口后引用仍有效。

### 日常操作

1. **短按一次下键**，或使用普通键盘按 **⌃⌥⌘J**，唤起 Codex 并尝试聚焦输入框。
2. **短按上键**开始说话，再按一次结束。
3. 检查转写结果，**短按中键**提交。

上键和中键由系统、豆包及当前应用直接处理。随叫采用非独占监听，不拦截这些原始按键，因此发送和语音输入依赖当前焦点与客户端设置。随叫不会自动选择项目、创建新对话或清空现有草稿。

### 桌面小精灵

- 拖动身体调整位置，位置保存到应用的 UserDefaults。
- 顶部固定显示“随叫，随到。”，底部没有额外名称或操作按钮。
- 点击菜单栏“随叫”，切换“隐藏桌面小精灵／显示桌面小精灵”。隐藏窗口不会退出后台监听。
- 语音动画根据观察到的左 Control 点按切换，**不是实际录音状态或麦克风音量监测**，可能与豆包状态不一致。
- 通过菜单栏“退出随叫”结束应用。

## 排查问题

应用每两秒写入本机状态文件：

```bash
cat /tmp/suijiao-runtime-status.json
```

| 字段 | 解释 |
| --- | --- |
| `accessibility` | 当前进程是否获得辅助功能权限 |
| `inputMonitoring` | IOKit 权限值：`0` 表示允许，`1` 表示拒绝，其他值不应当作已授权 |
| `capturedDevices` | 已连接并打开的匹配设备数量；字段名沿用早期实现，目前为非独占监听 |
| `wakeHotKeyStatus` | `0` 表示注册成功，**不等于唤起与定位成功** |
| `lastEvent` | 最近观察到的按键、唤起或校准事件 |
| `inputRemembered` | 当前进程是否保存了校准控件引用，不保证引用仍有效 |
| `status` | 当前状态或失败提示 |

常见情况：

- **按键无反应**：先检查 Free3 已开机、处于 P 档且通过蓝牙连接，再检查输入监控和设备数量。
- **普通键盘能触发、Free3 不能**：检查 Free3 的原始键值。不同固件的组合键报告方式可能不触发系统快捷键，因此程序还会直接识别 Free3 的 Control + Option + Command + J。
- **窗口出现但输入框未聚焦**：确认辅助功能权限，再执行输入框校准。当前自动识别依赖客户端的辅助功能结构，尚不可靠。
- **校准失败**：确认前台是目标客户端，且焦点位于真正的聊天输入框，而不是搜索框、文件编辑器或侧栏。
- **语音没反应**：先用普通键盘验证豆包免提快捷键、当前输入法、输入焦点和麦克风。
- **切换桌宠显示后快捷键仍无效**：隐藏与显示只改变窗口可见性，不会修复权限、设备或焦点问题。

按键诊断工具只观察匹配设备，不拦截按键。操作仍会传给当前应用，建议在空白测试文档中运行：

```bash
xcrun swift tools/detect-pager.swift 120
```

```bash

# 从实际 SwiftUI 视图生成静态预览，不启动后台监听
```

编译和预览验证不会替代实际桌面验收。完整链路至少需要验证：普通键盘与 Free3 分别触发、窗口实际到前台、输入框有光标、豆包开始与结束语音、回车提交、窗口失效后安全提示、桌宠显示隐藏。

项目结构：

```text
tools/
  Suijiao.swift          应用生命周期、权限状态、HID、快捷键、输入框校准
  Companion.swift        小精灵绘制、动画、拖动手势
  detect-pager.swift     独立按键诊断工具
packaging/Info.plist     应用包配置
scripts/build.sh        本机构建及 ad-hoc 签名
docs/assets/            界面预览
docs/architecture.md    实现说明与验证边界
```

本仓库不包含生成的 `.app`、个人按键测试记录、录音或聊天正文。应用源码没有实现录音、转写或上传服务；语音数据处理由外部豆包输入法负责。
